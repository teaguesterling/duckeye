# Test fixtures

## `test.zim`

Vendored from the zim extension's own test suite, so duckeye's ZIM cases run by
default instead of skipping. Before this, they ran only when `DUCKEYE_TEST_ZIM`
named an archive, which is how `-S` by title stayed broken for weeks while the
suite reported green.

| | |
|---|---|
| source | `teaguesterling/duckdb_zim`, `test/oracle/test.zim` |
| last changed there | `579e2fa` (2026-06-07) |
| generated by | `test/oracle/make_fixture.py` (`9c2e013`), via `pip install libzim` |
| sha256 | `320baaea517ccc1a9633f4db93fae78364ca3e29c918443a11cd34466caa41fd` |
| size | 60361 bytes |

Committed as a binary rather than regenerated here, deliberately: a `libzim`
dependency at test time would make the ZIM cases skip on any machine without it,
which is the failure mode vendoring exists to remove. The archive is a stable
**input**, unlike panduck's parsed fixtures, which are derived output and are read
from panduck's checkout instead.

What it covers: three HTML articles, one with an internal link; a redirect
(`A/Photosynth` → `A/Photosynthesis`); non-HTML entries (`I/logo.png`,
`style.css`); a main page; full metadata; full-text indexing.

Known gaps, both raised by the zim extension's maintainer: every article is a
single `<h1>`, so the outline check passes for any implementation that gets
heading levels wrong; and no entry has invalid UTF-8. A `make_fixture.py` change
adding an h1/h2/h2/h3 article and a non-UTF-8 entry has been proposed. **If it
lands, re-vendor** and update the checksum above.

Verify:

    sha256sum fixtures/test.zim

## `multiline.pdf`

A hand-made 501-byte, one-page PDF whose single text object wraps across three
lines, with a **hyphenated** break in the middle:

    BT /F1 12 Tf 72 720 Td 14 TL
    (The quick brown fox jumps over the) Tj T*
    (lazy dog and then contin-) Tj T*
    (ues onto a third line of text.) Tj T*
    ET

It is the smallest input that exercises line joining. `pdftotext -layout` keeps
the three lines and the `contin-` hyphen. duckeye must give one paragraph —
"…jumps over the lazy dog and then continues onto a third line of text." — with
a space at the soft break and no hyphen at the hard one. The de-hyphenation
itself happens in the `pdf` extension's text extraction; duckeye's part is joining
the lines into a single paragraph.

It also surfaced a defect in duckeye's own PDF path: every PDF's `page_break`
marker had a NULL `level` and shared its `element_order` with the block after it,
so `duck_blocks_validate` rejected every PDF duckeye produced. `test.sh` asserts
PDF blocks validate, against this fixture and its generated two-page PDF.

Origin: created by hand while working on PDF text extraction (file dated
2026-09-05); it sat untracked in the repo root until it was given a test.
